# Implementation notes

This document collects implementation and validation information previously distributed across code comments, configuration comments and the public release. It distinguishes the current implementation from evidence about the original experiments.

## Released checkpoints and validation status

The [v1.0.0 release](https://github.com/li-jiachen/STCMTrack/releases/tag/v1.0.0) provides the original Anti-UAV410 base and LTCP files. The release states that these files have been retained unchanged, have not been repaired or replaced, and have not been validated to reproduce the paper's scores with the current implementation.

The same release reports that the base contains query values that overflow FP32 LayerNorm, that a CPU test produced NaN predictions, and that the current checker rejects that base. These are statements in the public release; this documentation cleanup did not execute the released weights or independently repeat that CPU test. Evaluation requires a valid checkpoint. Identifying a file by its published hash does not establish that it is numerically suitable for evaluation.

Both original `.bin` files use Safetensors and contain incremental model state. The implementation loads the official DINOv2 ViT-B/14 weights for the frozen backbone before loading that incremental state. The files do not include the training-snapshot provenance needed to establish which training snapshot produced them. Their published hashes identify the released files, rather than certify their experimental origin. New exports carry explicit source metadata; no training provenance is invented for the legacy pair.

## Independent baseline and variant mapping

Table 2 row 1 selects the independent SPMTrack baseline, based on [WenRuiCai/SPMTrack](https://github.com/WenRuiCai/SPMTrack) at commit `c581fe27231f3e16c38578e47daddadfaf6ffd7d`. It retains three templates, two-search interval sampling, propagated query state, head-input feature reweighting and online template memory. It requires separately trained SPMTrack weights. A single-template STCMTrack checkpoint is not an SPMTrack checkpoint regardless of its filename.

Rows 2–8 select STCMTrack with the corresponding LTCP, MCC and RGTC switches. They share the STCMTrack base and non-component settings. Row 1 retains the separate SPMTrack structure and inference path. All eight configurations share the public external training and evaluation defaults. In particular, the current public configurations use a zero Hann penalty for both model families.

The variant checker establishes static configuration and implementation mappings. Such a mapping does not establish that the reported paper scores were generated by the current code, or that the code has reproduced those scores.

## Explicit paper settings and additional defaults

The Anti-UAV datasets and two-stage training budget follow the paper's explicit settings. The SPMTrack port uses the shared 80-epoch stage-1 budget rather than the upstream 170-epoch, GOT-10k/LaSOT/TrackingNet/COCO setup. Its model and temporal mechanisms remain independent of STCMTrack.

Settings omitted by the paper are fixed implementation choices. The public configurations share global batch size 4; 2048 training and 4096 validation samples per epoch; AdamW with learning rate `1e-4` and weight decay `0.1` without per-parameter overrides; cosine scheduling without warm-up and minimum learning rate 0; hard-center targets with radius 0; equally weighted BCE and GIoU; mean frame loss; joint flip/color augmentation; temporally consistent search-crop jitter; zero Hann penalty; evaluation search-crop minimum object size 1; and disabled `torch.compile` and efficiency assessment.

These unspecified defaults remain unverified against the original experiments. Sharing these defaults does not imply reproduction of upstream SPMTrack results or the paper's scores. The configuration checker distinguishes explicitly stated paper settings from the additional public defaults.

## Interpretation of numerical checks

The weight and tracking-output checks reject invalid or non-finite values. Tests also deliberately construct non-finite or extremely large tensors to exercise those checks. Those synthetic tests are not records of failed benchmark evaluations. Likewise, comments documenting handled upstream SPMTrack issues describe the upstream porting work; they do not independently establish the cause of the released STCMTrack weight problem.
